## 4. Задание 1. Terraform

### 4.1. Подготовка окружения

Terraform установлен и проверен командой `terraform version`. В каталоге `terraform-docker` создан файл `main.tf`. Инициализация выполнена командой:

```powershell
terraform init
```

Результат: `Terraform has been successfully initialized!`. Для проверки конфигурации использованы `terraform fmt`, `terraform validate` и `terraform plan`.

### 4.2. Создание Docker-инфраструктуры

В Terraform описаны два ресурса: `docker_image.nginx` и `docker_container.nginx`. Изначально контейнер `lab5-terraform-nginx` был опубликован на порту 8000, внутренний порт Nginx — 80.

```powershell
terraform plan
terraform apply
terraform state list
```

Создание контейнера было подтверждено через Docker и открытие стандартной страницы **Welcome to nginx!** в браузере.

### 4.3. Изменение инфраструктуры

Внешний порт сначала планировалось изменить на 8080, но он уже был занят другим контейнером. Чтобы не затрагивать сторонние Docker-ресурсы, выбран свободный порт **8090**.

```powershell
terraform validate
terraform plan
terraform apply -auto-approve
docker ps --filter "name=lab5-terraform-nginx"
```

Terraform показал план замены контейнера: `Plan: 1 to add, 0 to change, 1 to destroy`. Применение завершилось сообщением `Apply complete! Resources: 1 added, 0 changed, 1 destroyed.`. Docker подтвердил сопоставление портов `8090->80/tcp`, браузер по адресу `http://localhost:8090` отобразил **Welcome to nginx!**.

### 4.4. Удаление ресурсов

```powershell
terraform plan -destroy
terraform destroy -auto-approve
```

Контейнер лабораторной работы был удалён. При удалении общего образа `nginx:latest` возник конфликт: образ использовался другим контейнером. Во избежание нарушения работы иных проектов образ не удалялся принудительно. После проверки отсутствия `lab5-terraform-nginx` оставшаяся запись о разделяемом образе была исключена из Terraform state:

```powershell
terraform state rm docker_image.nginx
terraform state list
```

Последняя команда не вывела ресурсов. **Важно:** удаление записи из состояния не равно физическому удалению Docker-образа.

### 4.5. Входные переменные

В файле `variables.tf` объявлены переменные `container_name` со значением `lab5-terraform-nginx` и `external_port` со значением `8090`. В `main.tf` они используются как `var.container_name` и `var.external_port`.

```hcl
variable "container_name" {
  description = "Name of the Docker container"
  type        = string
  default     = "lab5-terraform-nginx"
}

variable "external_port" {
  description = "External port for Nginx"
  type        = number
  default     = 8090
}
```

Использование переменных позволяет настраивать инфраструктуру без изменения самой логики ресурсов.

### 4.6. Выходные значения

В `outputs.tf` определены выходные значения `container_name`, `container_id`, `external_port` и `application_url`. После `terraform apply -auto-approve` выполнена команда:

```powershell
terraform output
```

Подтверждённые результаты:

```text
application_url = "http://localhost:8090"
container_name = "lab5-terraform-nginx"
external_port = 8090
container_id = "<идентификатор, созданный Docker>"
```

Значение `container_id` действительно было получено; здесь оно не воспроизводится полностью. Таким образом, работа переменных и выходных значений проверена.

## 6. Ответы на контрольные вопросы

### 1. Для каких задач применяется Ansible?

Для автоматизации настройки серверов, установки пакетов, управления службами, развёртывания приложений и выполнения однотипных действий на группе хостов.

### 2. Какие способы управления серверами применяются в Ansible?

Разовые команды **Ad Hoc** и декларативные сценарии **Playbook**. Обычно Ansible связывается с Linux-узлами по SSH; для Windows применяются поддерживаемые способы подключения, например WinRM.

### 3. Что входит в состав Ansible Playbook?

Это YAML-документ, содержащий один или несколько plays. В каждом play указывают целевые `hosts`, задачи `tasks`; могут использоваться `vars`, `become`, `handlers` и `roles`.

### 4. Что такое группы узлов (хостов) в Ansible?

Логические группы управляемых машин в Inventory, например `[webservers]` и `[dbservers]`. Группа позволяет адресовать несколько серверов одним именем.

### 5. Как одной командой выполнить ping группы хостов?

```bash
ansible webservers -i inventory.ini -m ansible.builtin.ping
```

Модуль проверяет работоспособность подключения Ansible и возможность выполнить Python на управляемом узле. Успешный ответ содержит `pong`; это не ICMP ping.

### 6. Что такое роль Ansible?

Роль — повторно используемый комплект задач, обработчиков, переменных, шаблонов и файлов в стандартной структуре каталогов. Например, роль для настройки Nginx.

### 7. Что такое файл инвентаризации Ansible и как он используется?

Inventory перечисляет управляемые узлы, их группы и параметры соединения. Пример:

```ini
[webservers]
192.168.1.10
192.168.1.11
```

Выбирается ключом `-i inventory.ini`.

### 8. Что такое специальная команда Ansible?

Обычно имеется в виду **Ad Hoc команда** — единоразовый вызов модуля без написания Playbook, например `ansible all -i inventory.ini -m ansible.builtin.ping`.

### 9. Как перезапустить службу с помощью Ansible?

```bash
ansible webservers -i inventory.ini -b -m ansible.builtin.service -a "name=nginx state=restarted"
```

Необходимы соответствующие права на целевых хостах.

### 10. Что такое HashiCorp Terraform?

Terraform — инструмент описания и управления инфраструктурой как кодом. С помощью провайдеров он создаёт, изменяет и удаляет ресурсы в Docker, облачных и других системах.

### 11. Что такое Infrastructure as Code (IaC)?

IaC — управление инфраструктурой через версионируемые декларативные или программные определения вместо ручной настройки. Это повышает повторяемость и проверяемость изменений.

### 12. Как установить Terraform?

Скачать официальную сборку и добавить исполняемый файл в `PATH`, либо применить менеджер пакетов. Для Windows использовалась команда:

```powershell
winget install -e --id Hashicorp.Terraform
terraform version
```

### 13. Что такое провайдер в Terraform?

Плагин, который предоставляет Terraform типы ресурсов и взаимодействие с API определённой системы. В этой работе использовался `kreuzwerker/docker`.

### 14. Объясните базовую структуру файла конфигурации Terraform.

Блок `terraform` объявляет требования к версиям и провайдерам; `provider` настраивает взаимодействие; `resource` описывает управляемый объект; `variable` задаёт входные параметры; `output` публикует результаты. Файлы используют синтаксис HCL.

### 15. Что такое файл состояния Terraform?

Обычно `terraform.tfstate`: сведения об объектах, которыми управляет Terraform, их атрибутах и соответствиях ресурсам конфигурации. Состояние может содержать чувствительные сведения и не должно без проверки публиковаться в открытом репозитории.

### 16. Для чего нужна команда terraform destroy?

Для построения и применения плана удаления ресурсов, находящихся под управлением данной конфигурации Terraform. Следует предварительно проверить план, чтобы не удалить чужие ресурсы.

### 17. Что такое состояние в Terraform?

State фиксирует текущие сведения об управляемых ресурсах. Конфигурация описывает **желаемое** состояние; Terraform сравнивает его с известным состоянием и реальными ресурсами, чтобы рассчитать действия.

### 18. Как определить зависимости в Terraform?

Обычно автоматически по ссылкам между ресурсами:

```hcl
image = docker_image.nginx.image_id
```

Для зависимостей, которые нельзя выразить ссылкой, используют метааргумент:

```hcl
depends_on = [docker_image.nginx]
```
